# STEP 5 동시성 제어 및 테스트 보고서

## 1. 개요
콘서트 예약 시스템의 핵심 로직인 좌석 예약과 잔액 충전에 대해 동시성 제어를 적용하고 이를 검증한다.

## 2. 동시성 이슈 발생 지점 및 해결 방안

### 2.1 좌석 예약 (Seat Reservation)
- **문제**: 여러 사용자가 동시에 동일한 좌석을 예약할 때 중복 예약이 발생할 수 있음.
- **해결**: Database의 원자적 업데이트(Conditional Update)를 활용하여 상태가 `AVAILABLE`인 경우에만 업데이트하도록 구현.
- **한계점 (리뷰 포인트)**:
    - `reserved_until` 조건을 쿼리에서 누락하여, 예약 시간이 만료된 좌석을 재예약할 때 로직이 정상적으로 동작하지 않을 수 있음.
    - 낙관적 락을 적용할 수도 있었으나 구현의 단순함을 위해 Update 조건을 활용함.

### 2.2 잔액 충전 (Point Charge)
- **문제**: 충전 요청이 동시에 발생할 경우 갱신 분실(Lost Update) 문제가 발생하여 잔액이 부정확해질 수 있음.
- **해결**: JPA의 `PESSIMISTIC_WRITE` (비관적 락)을 사용하여 트랜잭션 내 조회를 직렬화함.
- **한계점 (리뷰 포인트)**:
    - 락을 획득하기 전에 일반 조회를 먼저 수행하고 로직을 타는 등, 락의 범위가 불필요하게 넓거나 획득 시점이 늦어 레이스 컨디션의 가능성을 완벽히 차단하지 못함.

## 3. 테스트 결과
- 멀티스레드 환경에서 `CountDownLatch`를 활용한 테스트 수행.
- **테스트 한계**:
    - 스레드 수가 적어(5개) 실제 고부하 상황을 충분히 재현하지 못함.
    - Assert 문이 `isGreaterThan(0)`과 같이 느슨하여, 정확히 1명만 성공했는지 검증하지 못함.
    - `Thread.sleep()`에 의존하는 테스트가 포함되어 실행 환경에 따라 결과가 달라질 수 있는 Flaky함을 내포함.

## 4. 스케줄러 구현
- `ReservationScheduler`를 통해 5분 이상 경과된 예약 건을 자동으로 취소 처리.
- **문제점**: 결제 완료 여부(`status='CONFIRMED'`)를 정교하게 체크하지 않아 이미 결제된 건도 취소될 위험이 있음.
