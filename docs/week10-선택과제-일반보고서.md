# 10주차 선택과제 보고서 (장애 대응 매뉴얼, 개선본)

## 1. 목적
- 부하 테스트에서 확인된 위험 구간(예약/확정 API의 피크 지연)을 운영 장애 관점으로 표준화한다.
- 장애 탐지 -> 전파 -> 복구 -> 회고를 시간 기준으로 정의해, 담당자 의존도를 낮춘다.

## 2. 장애 등급 및 목표 복구 시간
### 2.1 장애 등급
- `SEV-1`
  - 기준: 예약/확정 API 성공률 95% 미만이 5분 이상 지속, 또는 전체 서비스 핵심 기능 중단
  - 목표: 30분 내 임시 복구, 24시간 내 RCA 제출
- `SEV-2`
  - 기준: 성공률 95~98% 또는 p95 2초 초과 10분 지속
  - 목표: 60분 내 안정화, 48시간 내 RCA 제출
- `SEV-3`
  - 기준: 부분 기능 지연/경고성 지표 이상
  - 목표: 영업일 기준 3일 내 개선 반영

### 2.2 SLA/SLO 연동 지표
- 예약 API p95: 900ms 이하
- 확정 API p95: 900ms 이하
- 전체 성공률: 99.0% 이상
- Kafka consumer lag: 3,000건 이하 유지

## 3. 탐지 및 알림 기준
- APM/로그 기반 알림 룰
  - `Rule-1`: 5xx 비율 3% 초과 3분 -> 경고
  - `Rule-2`: 예약/확정 p95 1.5초 초과 5분 -> SEV-2 후보
  - `Rule-3`: 성공률 95% 미만 5분 -> SEV-1 즉시 선언
  - `Rule-4`: DB 락 대기 1초 초과 쿼리 100건/5분 -> 원인 조사 트리거
  - `Rule-5`: Kafka lag 10,000건 초과 3분 -> 소비 지연 장애 후보
- 알림 채널
  - 1차: Slack `#ops-alert`
  - 2차: 담당자 전화/메신저 콜

## 4. 주요 장애 시나리오와 대응
### 시나리오 A: 피크 트래픽으로 예약/확정 지연
- 징후
  - p95 2초 이상, 타임아웃 증가, 락 획득 재시도 증가
- 즉시 조치
  - 읽기 부하 비중이 높은 조회 트래픽 우선 제한
  - 인스턴스 수평 확장
  - 확정 API 타임아웃/재시도 정책 임시 하향 조정
- 근본 대응
  - 트랜잭션 범위 축소, 락 범위 세분화, 병목 쿼리 개선

### 시나리오 B: DB 락 경합/데드락 증가
- 징후
  - deadlock 로그 급증, lock wait timeout 증가
- 즉시 조치
  - 문제 트랜잭션 샘플링 후 hot key 구간 우회
  - 배치/스케줄러 일시 중지로 DB 여유 확보
- 근본 대응
  - 인덱스 보강, 쿼리 순서 정렬, 업데이트 충돌 경로 재설계

### 시나리오 C: Kafka 소비 지연
- 징후
  - consumer lag 누적, 후속 데이터 반영 지연
- 즉시 조치
  - consumer 재기동, 파티션/컨슈머 수 재조정
  - 장애 시간대 이벤트 재처리 큐 분리
- 근본 대응
  - 멱등 처리 점검, 실패 이벤트 DLQ 운용, lag 알림 세분화

## 5. 타임라인 기반 실행 절차 (Runbook)
1. `T+0 ~ T+5분` 탐지/선언
- 온콜 담당자가 알림 확인 후 SEV 등급 선언
- 영향 API/기간/현재 지표를 슬랙에 공지

2. `T+5 ~ T+15분` 원인 분류
- 앱/DB/Redis/Kafka 중 우선 병목 축 분류
- 최근 배포 이력, 설정 변경, 트래픽 급증 여부 확인

3. `T+15 ~ T+30분` 임시 복구
- 스케일 아웃, 트래픽 제한, 문제 기능 임시 degrade
- 성공률/지연 지표 정상화 여부 확인

4. `T+30분 이후` 안정화/모니터링
- 30분 연속 임계치 이내면 상황 종료 선언
- 재발 가능성 높은 설정은 즉시 롤백 또는 고정
